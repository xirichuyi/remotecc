# RemoteCC（macOS 原生客户端）

SwiftUI 客户端，通过系统 SSH 使用服务器上的 Claude Code。需要 macOS 14+ 和 Xcode 15.3+（或对应的命令行工具）。

## 构建

```sh
# 在仓库根目录安装打包服务端程序所需的 Claude Agent SDK
npm ci --ignore-scripts
# 生成 macos/dist/RemoteCC.app
macos/scripts/build-app.sh
open macos/dist/RemoteCC.app
```

## 结构

- `Sources/RemoteCCCore`：只依赖 Foundation，包含 SSH、代理协议、任务恢复、文件、历史、存储和展示逻辑，可在 Linux 上编译测试。
- `Sources/RemoteCC`：SwiftUI / AppKit 界面，只在 macOS 上编译。
- `scripts/prepare-server.cjs`：把 `../src` 下的服务端程序（`remote-agent.cjs` 和基于官方 SDK 的任务进程）打包进应用资源。

本地数据保存在 `~/Library/Application Support/RemoteCC Native`，与 Electron 版互不影响。

## 日常操作

- 侧栏顶部管理多台机器。添加机器只需 SSH 地址和可选端口，不需要填写开始目录；成功连接后自动发现这台机器上的全部 Claude Code 历史。
- 机器首页显示最近对话。点击已有对话会恢复原工作目录；新对话默认在远端主目录开始。机器切换不会主动断开其他机器，历史、同步状态按机器隔离。
- 添加机器不会覆盖已保存的连接。重启后恢复上次使用的机器；SSH 连接成功但历史扫描失败时保留连接并提示重试。
- 侧栏「新建对话」或 `⌘N` 新建对话；离线也可写草稿。右键会话可重命名、固定、归档或导出。
- 快捷建议仅在草稿为空时显示，点击后填入草稿并聚焦输入框。
- 切换项目会检查远端目录，新建对话并迁移未发送的草稿与附件；原对话继续保留。文件浏览与切换项目是独立操作。
- 模型按钮直接选择远端模型；自定义模型和其他参数在「更多设置」中配置。
- 向上滚动或点击消息阅读、选择文本时暂停自动跟随；点击浮动的「回到最新」恢复跟随。
- 思考内容使用可展开卡片，生成中显示末尾预览，长内容限高；只显示远端实际提供的内容。工具调用分别显示执行中、完成、失败、停止和历史状态，展开查看命令、差异与输出。
- 权限请求有独立确认卡，离线或提交中禁止重复提交，不用默认回车批准。失败回复可将上一条请求及附件放回空输入框编辑，已有草稿不会被覆盖，也不自动重试远端操作。
- 代码块提供语言标记、限高滚动和复制反馈；支持常见语言的基础语法着色，超长代码退回纯文本以保持响应。历史图片仍受服务端历史接口限制，仅显示占位说明。
- Debug 构建的「工作区 → 聊天交互预览」提供本地示例状态验收，不会发送消息或执行命令；Release 构建不包含这个入口。
- 输入 `/` 选择远端命令，输入 `@` 附加文件；Enter 发送，Shift + Enter 换行。
- SSH 端口可留空以使用系统配置；填写时必须是 1–65535 的整数。

## 状态与恢复

- 「所有机器的任务」集中显示待确认、后台任务和未读结果；离线机器提示状态可能过期。系统通知默认关闭，可手动启用。
- 导入的历史对话在可见且在线时每 30 秒增量同步，也可手动刷新；由本客户端常驻进程管理的会话走任务快照，不混合导入历史。
- 附件失败可重试；已发送图片可按需加载缩略图，文件可打开或下载。
- 用量面板显示 SDK 返回的 token、费用估计及可用的上下文信息；历史会话无常驻进程时不显示虚构的上下文占用。
- 文件检查点先预览再确认，预览过期或文件变化会阻止回退。仅恢复 SDK 跟踪的文件，不回退聊天，也不保证恢复 Bash 或子代理的文件改动。
- 「新建隔离工作区」从当前 Git HEAD 创建分支和 worktree，原目录未提交改动不迁移。
- 已适配权限、问题和表单；尚无明确协议的新版通用用户对话类型不声明支持。
- 新增的远端能力需要新启动的任务进程；已有常驻任务不被强制中断升级。

### 传输异常修复与验证（2026-11-01）

- 下载使用同目录原子替换；替换失败保留旧目标，不再提前删除文件或目录。
- 下载校验完整字节数；故障注入验证断线/异常退出、截断但退出码为 0 均不覆盖旧文件，临时文件会清理。
- 上传按 256 KiB 等待管道写入，避免将整个文件排入内存；等待 stdout EOF 后解析完整服务端确认，校验大小后才报告完成。
- 传输进度携带机器与工作目录，切换到其他机器或项目不再显示错位进度。
- `REMOTECC_LIVE_HOST=axi REMOTECC_LIVE_LARGE=1 swift test --package-path macos --filter LiveRemoteTests` 通过真实 32 MiB 上传/下载逐字节比对；这不代表 1 GiB 上限、真实磁盘满或所有网络故障已验收。

### 唤醒恢复、双服务器与通知（2026-11-01）

- `RecoveryTests` 三项通过：本地 SSH master 存活但远端不可达、断开后迟到的连接结果不能复活连接、通知断线补报及机器隔离。

### 复用 UI 组件

聊天正文、工具 Markdown 输出和 Markdown 文件预览使用 MarkdownUI 2.4.1，而不再使用本地简化解析器绘制正文。该库处于维护模式，本项目固定版本并提交 Package.resolved。GFM 表格、嵌套列表、任务列表、引用由组件处理；代码块保留应用的复制/高亮外壳，显式 Markdown 文件链接继续路由到远端工作区。旧版将行内代码中的裸路径自动转为链接的扩展暂未迁移，裸路径目前显示为代码文本。

版权文件位于 Resources/ThirdParty，build-app.sh 会将其打包进应用。当前侧栏、输入区和工具卡片仍为 SwiftUI 实现；并未移植其他客户端的 React 组件。

### 网络体验复核（2026-11-02）

- 历史页面加载按会话及分页方向合并并发请求；慢响应回来时重新检查会话所有权，避免与新发起的本地任务竞争。
- 重连、文件写入和文件监听变更只失效相应机器的目录缓存，避免干扰其他机器。
- 单次健康探测的 8 秒超时只限制该请求等待；不能直接视为整条 SSH 连接死亡。后续下载截断修复增加了本地主连接存活检查，真正静默失联交给 OpenSSH 保活识别。周期检查另有 15 秒间隔，见下方真实黑洞测试结果。
- axi / Fermat 的真实并发上传、预览、专用 SSH master 中断与恢复连续两轮通过。测试只终止测试自己的连接，不操作应用连接。
- 第二轮 Fermat 12 次热文本预览（含远端版本校验）中位 135 ms、最大 220 ms；仅为当前网络样本，不是 p95/SLA，也不是弱网或模型首字延迟指标。
- 尚未完成定量的 100–500 ms RTT / 丢包 / 限速矩阵、长时间离线、硬件睡眠和模型首字延迟基准，不能据此宣称远程体验已与本地等价。32 MiB 重复字节文件仅验证传输完整性，不能用作吞吐性能结论。

- 同轮真实 axi 集成测试通过：32 MiB 上传/下载逐字节一致、附件 → Claude Edit → 检查点预览/应用 → 原始内容恢复，以及历史加载/刷新/去重/重连。

### 可重复的弱网测试

测试入口：`macos/Tests/RemoteCCCoreTests/NetworkExperienceTests.swift`。

- `REMOTECC_NETWORK_HOST=axi REMOTECC_NETWORK_MODEL=1 REMOTECC_OFFLINE_SECONDS=300 swift test --package-path macos --filter testShapedSSHAndFirstText`：独立 SSH ProxyCommand，注入每方向延迟、带宽上限、周期性停顿以及五分钟离线。可用 `REMOTECC_OFFLINE_SECONDS=0` 快速复测其他场景。
- `REMOTECC_NETEM_HOST=axi swift test --package-path macos --filter testRealPacketLossInIsolatedRemoteNamespace`：要求远端 Python、ip、tc 和创建网络命名空间权限。先建立上游 SSH socket，再在一次性网络命名空间内使用 loopback netem；不修改宿主机网卡、路由、防火墙。校验实际 dropped 计数和随机文件传输完整性。
- ProxyCommand 中的周期性停顿仅模拟重传等待，不能当作真实 IP 丢包；真正丢包由独立 netem 用例覆盖。
- 首字数据在 Swift 引擎首次观察到助手文本时采集，包含 SSH、SDK 启动/复用和模型服务耗时；不是屏幕绘制耗时，也不是排除了模型波动的客户端延迟。冷、热会话样本不可直接当成优化前后对照。
- 限速是每方向上限，文件传输耗时还包含元数据查询、SSH 子通道启动、版本检查和结束确认。随机数据避免压缩造成虚假的吞吐数字。
- 网络恢复优化：系统 NWPathMonitor 和 macOS 唤醒事件主动检查并重连仍被用户标记为需要连接的机器。远端单独恢复、但本机网络路径未变化时，仍依赖有退避的自动重试；不能承诺所有故障都即时恢复。
- 本轮修复还包括：下载等待期间响应 Task 取消；旧通道迟到的关闭回调不移除新通道；最多 4 个子目录并发刷新；刷新失败时保留并标注目录/文件快照。

| 测试代理基线 | 237 ms | 235 ms | 1.42 s |
| 额外 300 ms RTT | 537 ms | 533 ms | 2.00 s |

- 第三轮 netem 观察到 19 个实际丢包，1 MiB 上传/下载 7.23 s，逐字节一致；带计数校验的三轮均通过。
- 默认 Swift 回归：32 项中 28 项通过、4 项远端专项按默认跳过；专项按上面的环境变量单独执行。Node 服务端测试 63 项通过。

### 下载截断定位与持续运行复核（2026-11-02）

已确认一个确定性下载截断缺陷：健康探测的 `true` 命令超过 8 秒时，旧实现直接执行 `ssh -O exit`，关闭共享 ControlMaster；即使另一个 SSH 子通道仍在正常传输，也会同时被切断。回归用例 `testSlowHealthProbeDoesNotAbortAnActiveTransfer` 在修复前复现退出码 255、仅收到 312/400 字节；修复后完整收到 400/400 字节。

修复将 SSH 命令超时与确定的连接失败区分：探测超时后检查本地主连接是否仍存活，不再仅凭一次慢探测关闭它。真正失联仍由 OpenSSH 保活和后续检查识别；明确失败、用户主动断开继续按原有规则处理。探测慢时显示提示，恢复正常后清除；这种提示不再导致所有机器的能力缓存失效。

验证证据：

- 原始 MTU 65536、256 KiB、2% 丢包条件复跑四次，均完整，记录到实际丢包。历史单次失败没有完整的退出码和字节数日志，因此不能百分百追溯其唯一原因；以上修复的是已确定复现、可造成同类故障的因果链。
- 真实 2% 丢包叠加 10 秒慢探测：4 MiB 上传/下载逐字节一致，观察到 94 个丢包，传输持续 48.19 秒，主连接未被误杀。
- 真正静默黑洞：完全停止转发，不主动关闭连接，64.89 秒后检测出失联；解除黑洞并触发恢复入口后 2.96 秒可用。这是保活检测的样本，不应宣称所有故障都能 8 秒内识别。
- 真实 Claude 附件读写、检查点回退、历史加载及续接在修复后仍通过。
